# 拠点配置プランナー v2 改良 設計書

日付: 2026-07-13
対象ファイル: `palworld_base_planner_v2.html`

## 背景

`palworld_base_planner_v2.html` は拠点最適化(役職重要度+拠点枠数→最適パル配置を貪欲法+局所探索で計算)の実装途中版。既存コードをレビューした結果、以下4点の改良を行う。実装順は 0→1→2→3。

## 0. パル画像対応(JP⇔EN名前マッチング)

**課題**: `palworld_pals_clean.json`(287体、日本語名、GameWith由来、2026-07-11取得=1.0後)と `game_data/characters.json`(1123体、英語名+asset名、内部データマイン由来)の間にID対応が無い。

**重要な発見(2026-07-13調査)**: 作業適正パターンによるフィンガープリント照合を試したところ、287体中112体が一致せず、一致しない名前の傾向(シルフィア/シルティア等)から`game_data/characters.json`は**1.0リリース前の内部データマインで、1.0で追加された新パル72体が欠けている可能性が高い**と判明した。この`characters.json`は`palworld_combat_stats.json`(戦闘計算機で将来使う予定)の元データでもあるため、このプロジェクト全体に影響する既知の注意点としてObsidianの仕様書にも記録する。

**採用する方式(名前ベース、数値フィンガープリントより信頼度が高い)**:
1. `paldb.cc/ja/Pals`(1.0対応済み確認済み、日本語名と英語名が並記されている)をPlaywrightでスクレイピングし、JP名↔EN名のペア一覧を取得する(`dump_tables.py`と同じ手法)
2. 取得したEN名を`game_data/characters.json`の`pals[].name`と文字列一致させ、一致したら`icon`パス(例: `/icons/pals/T_Alpaca_icon_normal.webp`)を取得する
3. `game_data`に存在しない1.0新パル(72体のうちの一部)はEN名で一致しないため、画像なし(フォールバック表示)として扱う。件数をログに出す
4. 結果を `palworld_name_jp_en_map.json` として `palworld/` フォルダに保存(jp_name, en_name, icon_path[nullable]を持つ配列)。以後のタスクでも再利用できる中間データとして永続化する
5. `PAL_DATA` に `icon` パス(nullable)を追加し、パルカードに `<img>` で表示する(iconがnullの場合は現状通りテキストのみ)。HTMLは`game_data`フォルダと同じ階層に置く前提(相対パス参照、base64埋め込みはしない。詳細はCLAUDE.md参照)

**検証方法**: 画像が見つかった件数/見つからなかった件数をログに出し、ユーザーに報告する。既知の何体か(モコロン、メルパカ、アルパオーなど)が正しい画像に対応しているか目視確認する。

## 1. 作業速度スコアの正確性修正

**現状の問題**: `baseScore()` が `重要度(0-3) × pal.work[役職](作業適正Lv、生数値1〜9)` という単純な掛け算をしている。実際のゲームでは役職Lvと実速度の関係は非線形(`palworld_work_speed_table.json` 参照)で、単純な線形近似は不正確。

**修正方針**:
1. `palworld_work_speed_table.json` の `work_speed_by_role` を `WORK_SPEED_TABLE` としてHTML内に埋め込む
2. 各役職について「Lv1実測値を基準にした相対倍率テーブル」を実行時に構築する(例: 火おこしLv3 = 600/70 ≈ 8.57倍)
3. **Lv6以上の扱い**: 実測データが無いため、役職ごとに実測されているLv4→Lv5の伸び率で外挿する。
   - 火おこし/手作業/製薬グループ(Lv4→5が×3): Lv6=Lv5×3, Lv7=Lv6×3, ...
   - 水やり/種まき/採集/伐採/採掘/冷却グループ(Lv4→5が×2): 同様に×2で外挙
   - 発電(Lv4→5が×2): 同様に×2で外挿
   - 全役職一律「3倍」という誤った仮定はしない(役職によって実測伸び率が異なるため)
   - UI上に「Lv6以上は実測データが無く外挿値」の注記を表示する
4. `baseScore()` はこの相対倍率(Lv1=1.0とした指数的な値)を使って計算し直す。重要度スライダー(0〜3)の意味は維持する。

## 2. 世界樹パッシブ トグル

**追加データ**: 世界樹パッシブのうち作業速度に関係するのは「悪魔の手(作業速度+90%、デメリット: SAN値減少+15%)」のみ。他の世界樹パッシブ(次元跳躍・諸刃の聖剣など)は移動速度/攻撃/防御/HP系で拠点作業スコアには無関係のため対象外。

**実装方針**:
1. 拠点設定パネルに新トグル「世界樹パッシブも考慮」を追加(デフォルトOFF)
2. ONの時、`PASSIVE_POOL.speed` 候補に「悪魔の手 +90%」をデメリット情報付きで追加し、既存6種と合わせて上位4枠選出の対象にする
3. 選出された場合、パルカードのパッシブバッジに警告色で「デメリット: SAN値減少+15%」を併記する

## 3. ride情報バッジ表示

**実装方針**: `palworld_pals_clean.json` の `ride.rideable/fly/swim` を `PAL_DATA` に追加取り込みし、パルカードに小さいアイコンバッジ(乗れる/飛べる/泳げる。trueのものだけ表示)を追加する。スコア計算には影響しない表示専用の情報。

## スコープ外(今回やらないこと)

- パルの詳細図鑑ページ: 将来的にやりたいとの要望はあるが、今回はスコープ外(画像対応の中間データ`palworld_name_jp_en_map.json`は将来この機能でも再利用できる)
- 属性相性の倍率確定: 別トピック(既にObsidianの仕様書に未確定として記録済み)、今回のv2改良とは独立
- デザインの本格的な作り込み: CLAUDE.mdの方針通り、戦闘データが揃うまで保留

## 検証方法

- 修正後、いくつかの役職・拠点枠数パターンで計算結果が現行版と比べてどう変わるかを目視確認する
- 特にLv6以上を持つパル(モノクローナの手作業Lv8など)が入るケースで、外挿値が破綻していないか(異常に高スコアで独占しすぎないか)を確認する
- 世界樹パッシブトグルのON/OFF切り替えで結果が変わることを確認する
- rideバッジがtrue項目のみ正しく表示されることを確認する
