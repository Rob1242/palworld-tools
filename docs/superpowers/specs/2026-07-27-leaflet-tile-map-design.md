# 地図タイル化(Leaflet.js移行) 設計書

日付: 2026-07-27
対象ファイル: `palworld_map.html`(地図ビュー・パル像ビュー両方)

## 背景

颯太から「GameWith(gamewith.jp/palworld/433598)のマップは細かくズームしても鮮明に見えるのに、うちのサイトはただズームしてる感じでボケて見にくい」という指摘があった。

調査の結果:
- GameWithの地図は**Leaflet.js**(タイル地図ライブラリ、MITライセンス)で実装されており、地図をズームレベルごとに複数解像度のタイル画像(`z1/0_0.png`のような256px単位のファイル群)に事前分割して配信している。ズームすると別解像度のタイルに切り替わるため、常に鮮明。
- 一方うちのサイトは、1枚の背景画像(本土3072×3072px、世界樹4096×4096px)を`transform: scale()`で最大8倍までCSSで拡大しているだけ。ズームしても元画像のピクセルが引き伸ばされるだけでボケる。
- 既に世界樹エリアの背景画像として使っている**Nifrendil/pal-atlas**(GitHub、MITライセンス、Palpagos+世界樹両対応のオープンソース地図プロジェクト)が、本土用にも`palpagos.webp`(4096×4096px)を公開している。現行の本土画像(3072px)より高解像度で、世界樹側(既に4096pxで導入済み)と解像度も揃う。

## 方針

Leaflet.jsを地図エンジンとして導入し、pal-atlasの4096px素材から自前でタイルピラミッドを生成して、地図ビュー・パル像ビュー両方をタイル方式に置き換える。既存の座標データ(全JSON、0〜1の正規化x/y)はそのまま流用し、変換はレンダリング層のみで行う。

### 却下した代替案

- **現行の自作pan/zoomコードのままタイル画像だけ手動で差し替える案**: 新規ライブラリ依存は増えないが、Leafletが解決済みのタイル読み込み順序・キャッシュ・ビューポート外カリング・スムーズズーム・タッチ操作などを全部自前で再発明することになり、長期的な保守コストが高いため却下。
- **タイル化せず高解像度画像に差し替えるだけの案**: 作業量は最小だが、ズーム時の見え方が「CSSで引き伸ばしている」という体感自体は変わらず、颯太の指摘の核心(タイル切り替えによる鮮明さ)を解決できないため却下。

## 1. タイル生成パイプライン

- `scripts/build_map_tiles.py`(新規)を追加。pal-atlasの`palpagos.webp`(4096×4096)・`worldtree.webp`(4096×4096、既存の`game_data/maps/worldtree.webp`と同一ファイル)から、Pillowでズームレベルごとのタイル画像を生成する
- タイルサイズ256px、ズームレベルはLeaflet標準の2倍刻みで z0(256px全体1枚)〜z4(4096px、16×16枚)の5段階
- 出力形式はwebp(既存プロジェクトの慣例に合わせる)、出力先は `game_data/maps/tiles/{palpagos|worldtree}/{z}/{x}_{y}.webp`
- スクリプトは再実行可能にし、将来より高解像度な素材が見つかった場合にタイルを再生成できるようにする

## 2. 座標系

- `spawn_data`/`curated_landmarks`/`statue_data`/`tower_boss_data`/`merchant_data`/`fast_travel_data`等、既存の全データファイルは**変更しない**(正規化0〜1のx/yのまま)
- Leaflet側は`L.CRS.Simple`を使い、地図の`bounds`をタイル画素サイズ(4096×4096)に設定する
- マーカー生成時に `leafletLat = (1 - y) * 4096, leafletLng = x * 4096` の変換を行うヘルパー関数を1つ作り、全レイヤーで共通利用する(Leafletは南北=Y軸が地理座標的に上がプラスのため反転が必要)
- 世界樹の既存`worldToUv`変換式(Unreal座標→正規化座標)はそのまま前処理として維持し、Leaflet側の変換とは独立させる

## 3. マーカー/レイヤー移行

- 既存の「絶対配置div + CSS(%配置、`translate(-50%,-50%)`)」方式を `L.marker(latlng, {icon: L.divIcon(...)})` に置き換える
- レイヤーごとに `L.layerGroup()` を割り当てる。対象は以下の全種類:
  - 地図ビュー: 出現パル、フィールドボス、NPC、塔ボス、商人、ファストトラベル、カスタムマーカー(ユーザー追加)、密度ヒートマップ
  - パル像ビュー: パル像マーカー(12種)
- 既存のレイヤートグルUI(表示/非表示チェックボックス)は、対応する`L.layerGroup`の`addTo(map)`/`removeFrom(map)`切り替えに置き換える
- クリック時の詳細表示・ホバーツールチップは、Leaflet標準の`bindPopup`/`bindTooltip`に寄せる(現状の自作ツールチップ位置計算より少ないコードで済む見込み)
- 密度ヒートマップは現状通りCanvas重ね描き方式を維持する。Leaflet.heat等のプラグイン導入は今回のスコープ外

## 4. 既存機能の維持(回帰させてはいけないもの)

- 地域タブ切り替え(本土/世界樹) — タイルレイヤーとマーカーレイヤー一式をまとめて切り替える
- カスタムマーカーの追加/削除モード
- 密度ヒートマップのON/OFF
- パル像チェックリスト(localStorage、回収済み/未回収表示)
- 直リンク・クエリパラメータ(`?view=`, `?id=`, `?embed=1`)。特に`embed=1`はパル図鑑ページからのiframe埋め込みで使用中のため要確認
- 旧URL(`palworld_statues.html`等)からのリダイレクト先(`?view=statues`等)の挙動

## 5. ロールアウト順序

1. **パル像ビュー**(マーカー種類1つのみ、影響範囲が小さい)でLeaflet化・タイル化を先に実装し、動作確認・コミット・pushまで完了させる
2. 同じ基盤を使って**地図ビュー**(9レイヤー)に展開する。レイヤーが多いため、1〜2種類ずつ動作確認しながら進める
3. 各ステップでローカルサーバー+claude-in-chromeでの実機確認を行ってからコミットする(パン・ズーム・マーカークリック・レイヤートグル・地域切替・直リンク・embedモード)

## スコープ外(今回やらないこと)

- pal-atlasの4096pxを超えるさらに高解像度な素材の調査(例: Kregap/palworld-mapが本土のみ8192px相当のタイルを公開しているが、2024年2月から更新が止まっており世界樹エリア非対応のため今回は不採用。将来的な追加検討課題として記録のみ)
- Leaflet.heat等によるヒートマップの本格的な作り直し
- モバイル操作(ピンチズーム等)の追加最適化。Leaflet標準のタッチ操作をそのまま使い、個別チューニングはしない

## 検証方法

- ローカルサーバー(`python3 -m http.server`)+claude-in-chromeで、パル像ビュー・地図ビュー双方について、パン・ズーム(深いズームで実際にタイル画像が切り替わり鮮明になることを画面キャプチャで確認)・各マーカーのクリック/ホバー・レイヤートグル・地域タブ切り替え・チェックリストのlocalStorage永続化・直リンク(`?id=`)・embed表示を一通り確認する
- 本番反映後、`curl`でタイル画像が実際にGitHub Pages上で200を返すことを確認する
