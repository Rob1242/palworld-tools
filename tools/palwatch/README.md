# palwatch — サーバーの様子を見て、声でやり取りする

Palworld専用サーバーのセーブデータを読んで、出来事を知らせたりObsidianに書き留めたり、
声で質問に答えたりする。Macで動かす。

## なぜこの作りなのか

Palworldにはゲーム内チャットを読む手段が無く、Botがプレイヤーとして参加することもできない
(マイクラのMineflayerのようなものが存在しない)。そこで**ゲームの外側**で成立させている。

- 出力: Macから声、必要ならサーバーのREST APIでゲーム内にもテキスト表示
- 入力: **Macのマイク**で受ける。PS5で遊びながらMacに話しかける想定
- データ: サーバー側(VM)が5分ごとに更新しているバックアップを読む

音声はすべてMac内で処理され、外部には送られない。

## 準備

```bash
brew install sox whisper-cpp
mkdir -p ~/.local/share/whisper && cd ~/.local/share/whisper
curl -LO https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin
```

`config.example.json` をコピーして `config.json` を作り、合言葉などを埋める。
**config.json は合言葉とAPIキーを含むので、絶対にコミットしないこと**(.gitignore済み)。

初回の録音時にmacOSのマイク許可を求められるので、許可する。

## 使い方

```bash
node palwatch.mjs            # 1回だけ確認して、変化があれば知らせる
node palwatch.mjs --watch    # 常駐(既定5分ごと)。遊ぶ時はこれを立ち上げておく
node palwatch.mjs --talk     # 話しかけモード。「+」を押してから喋る
node palwatch.mjs --wake     # 呼びかけモード。呼ばれたら聞き取りを始める
node palwatch.mjs --advice   # 拠点編成の助言だけ
node palwatch.mjs --voices   # VOICEVOXの話者一覧(番号を調べる)
node palwatch.mjs --quiet    # 声を出さず記録だけ

node palwatch.mjs --miccheck   # 座る場所から声が届いているか測る(最初にこれ)
node palwatch.mjs --collect    # ふだん喋っている声をそのまま貯める(推奨)
node palwatch.mjs --build      # 貯めた声から声紋を作る
node palwatch.mjs --enroll     # 台本を読んで声紋を作る(--collect が使えないとき)
node palwatch.mjs --enroll --quick   # 短縮版(6回)
node palwatch.mjs --calibrate  # 自分の声と弾きたい音の差を測り、しきい値を決める
node palwatch.mjs --voicebank  # 貯まった声の状況を見る(--all で全件)
node palwatch.mjs --drop <id>  # 覚えのない録音を消す
node palwatch.mjs --relearn    # 貯まった声で声紋を作り直す
```

## 話しかけて答えられること

ゲームのデータで確実に答えられる範囲に絞っている(外部のAIには繋いでいない)。

- 「今何体いる」 → 所持数と種類数
- 「図鑑は何種類そろってる」 → 進捗と残り
- 「一番強いパルは」 → 個体値合計が最大の個体
- 「拠点はどうすればいい」 → 手薄な役職・余っている役職・各役職の最適個体
- 「アヌビスは何体いる」 → その種の所持数と最良個体

聞き取りではカタカナが崩れることがあるため(「セクメト」→「セクメと」)、
パル名は平仮名に寄せて照合している。

## ファイル構成

| `base-advice.mjs` | 拠点プランナーと同じ作業速度テーブルで手持ちを評価 |
| `voice.mjs` | 録音・意図判定 |
| `stt.mjs` | 録音と聞き取り(whisperの呼び出しと後処理)。全モードで共有 |

## 調整できるところ

`config.json` で変えられる。

- `voice` — macOS標準の声(`Kyoko` / `Eddy` / `Flo` / `Grandma` / `Grandpa`)
- `speakMinWeight` — この重要度以上の出来事だけ読み上げる(既定3)
- `maxSpeechPerTick` — 1回にまとめて喋る上限(既定3)
- `intervalMinutes` — 見守りの間隔(既定5分)
- `voiceSilenceSec` — 何秒黙ったら話し終わりとみなすか(既定1.2秒)
- `talkKeys` — `--talk` で録音を始めるキー(既定 `["+", "＋"]`)。Enterは不要
- `duckAudio` — ルナが喋っている間、システムの出力音量を一時的に下げるか(既定`true`)。
  YouTube等を見ながらでも声が埋もれないようにするためのもの。喋り終わったら元の音量に戻す。
  macOSはアプリ別の音量調整が無いため、システム全体の音量を上げ下げする形で実現している
- `duckVolumeFactor` — 下げる先の音量(現在の音量に対する倍率、既定`0.35`=35%)

## 声をVOICEVOXにする

[VOICEVOX](https://voicevox.hiroshiba.jp/) を入れて起動しておくと、そちらの声で喋る。
入れていない、または起動していない場合は自動でmacOS標準の声に戻るので、
設定を戻す必要はない。

### 導入

公式サイトからダウンロードする。M1/M2/M3なら **「CPU(Apple)」版** を選ぶ。
アプリを起動している間だけ使える(内部で音声合成サーバーが動く仕組みのため)。

### 話者を選ぶ

VOICEVOXを起動した状態で番号を調べ、`config.json` の `voicevoxSpeaker` に入れる。

```bash
node palwatch.mjs --voices
```

### 設定

- `useVoicevox` — `false` にすると常にmacOS標準の声を使う
- `voicevoxSpeaker` — 既定の話者番号
- `voicevoxSpeed` — 話す速さ(1.0が標準)
- `voicevoxPitch` — 声の高さ(0.0が標準)

### 内容によって声色を変える

VOICEVOXは同じキャラでもスタイル(ノーマル/あまあま/ささやき等)ごとに別の番号が
振られている。それを場面ごとに割り当てられる。

```json
"voicevoxStyles": {
  "catch":   7,    // パルを捕まえた時(うれしい報告)
  "levelup": 7,
  "first":   3,
  "gone":    22,   // いなくなった時(落ち着いた声)
  "advice":  22,   // 拠点の助言
  "reply":   3,    // 話しかけへの返事(通常の受け答え)
  "unsure":  22    // わからない/データが無い時(しょんぼりした声)
},
"voicevoxToneSpeed": { "catch": 1.15, "advice": 0.95 },
"voicevoxTonePitch": { "catch": 0.05 }
```

**書かなかった場面は既定の話者になる**ので、全部埋める必要はない。
番号は `--voices` で調べる。同じキャラの別スタイルを指定すれば、声質は保ったまま
話し方だけが変わる。

場面の名前は `first`(記録開始) / `catch`(捕獲) / `levelup` / `gone`(手放した) /
`advice`(拠点の助言) / `reply`(会話の返事、内容がどの分岐にも当てはまらない普通の受け答え) /
`unsure`(「まだ持ってないね」「わからなかった」など自信が無い/データが無い返事)。

`reply`・`advice`・`unsure` は `--talk`・`--wake` モードの受け答えの**内容によって**
自動的に切り替わる(`voice.mjs`の`interpret()`が返答ごとにどの場面かを判定している)。
拠点の相談なら`advice`、わからない/持っていない系の答えなら`unsure`、それ以外は`reply`になる。

### 注意

VOICEVOXのキャラクターには**それぞれ利用規約がある**。個人で楽しむぶんには問題ないが、
動画や配信など公開する形で使う場合はクレジット表記が必要になることが多いので、
公式の規約を確認すること。

## 呼びかけモード(--wake)

「ルナ」と呼びかけると反応する。**追加の登録もAPIキーも要らない。**

当初Picovoiceを使う予定だったが、2026年6月30日に個人利用プランが廃止されたため、
すでに入れてあるwhisperだけで実現している。

### 仕組み

1. soxが無音を監視して待つ(音量を見ているだけなのでCPUをほとんど使わない)
2. 声が始まったら録音し、黙ったところで自動的に切る
3. whisperで文字にして、呼びかけ語が含まれているか見る

**「ルナ、今何体いる」のように呼びかけと用件を続けて言える**のがこの方式の利点。
呼びかけだけの場合は「なに?」と返してから用件を聞く。

### 誤検出をどう減らしたか(2026-08-04)

**YouTubeやテレビの音で反応してしまう問題の主因は、照合の規則そのものだった。**

以前は「先頭が1文字欠けた形」を認めていた(「ルナ、拠点は」→「な、拠点は」)。
`ルナ` の頭が落ちると `な` になるので、**`な` で始まる日本語が全部通っていた。**
実測すると、呼びかけでない文26件のうち12件がこれで誤検出されている。
「なんか」「なるほど」「なので」——動画の音声には無数に出てくる。

しかもこの規則は、救うはずの崩れ方を救えていなかった。
語彙のヒント(`--prompt`)を入れてから頭が欠ける崩れは起きなくなり、
小声や遠い声で実際に起きるのは `リューナ` のような別の崩れ方だった。
**効かない規則のために誤検出を抱えていた。**

今の規則は3つ:

1. **文頭付近(8文字以内)にあること** — 話の中に出てきた「ルナ」で反応しない
2. **直後で語が切れていること** — `ルナティック` `ルナルナ` `ルナシー` で反応しない
3. **表記ゆれは `wakeWords` に足す** — 規則を緩めず、許す語を目に見える形で増やす

| | 誤検出 | 見逃し |
|---|---|---|
| 以前 | 12/28 | 1/9 |
| **今** | **0/28** | **0/9** |

崩れた読みを拾いたくなっても、規則を緩めてはいけない。`wakeWords` に足すこと。
どの語を許したかが設定に残るので、後から効果を確かめられる。

カタカナが平仮名に崩れるケース(「ルナ」→「るな」)にも対応している。

### 音で選別する(3段構え)

言葉の照合だけでは、動画の中で本当に「ルナ、」と言われたら通ってしまう。
音そのものでも選別する。**それぞれ単独では不十分なので、重ねて使う。**

| 段 | 見ているもの | 抜けるケース |
|---|---|---|
| 音量 (`wakeMinRms`) | 近くで話したか | 大音量で流されると通る |
| 声紋 (`speakerThreshold`) | あなたの声か | 録音環境が変わると揺れる |
| 言葉 (`wakeWords`) | 呼びかけたか | 動画内で呼ばれると通る |

音量の判定は聞き取りの**前**に走るので、動画を流している間はwhisperすら動かない。
負荷も下がる。

しきい値は両方 `--calibrate` が測って出す。**環境ごとに変わるので既定値は当てにならない。**

### 語彙のヒントが効く(2026-08-04)

whisperには `--prompt` で単語を前もって教えられる。これがいちばん効いた。

同じ音声で比べた結果:

| 設定 | 「ルナ、拠点の様子を教えて」 | 「ルナ、パルスフィアはいくつある」 | 時間 |
|---|---|---|---|
| small(ヒント無し) | `な 拠点の様子を教えて` | `パルスヒア` | 0.87秒 |
| **small + ヒント + VAD** | `ルナ、拠点の様子を教えて` | `パルスフィア` | 1.1秒 |
| large-v3-turbo + ヒント + VAD | 正解 | 正解 | 3.4秒 |

**モデルを大きくするより語彙を教えるほうが効く。**
turboは3倍遅いだけで、smallと同じ結果しか出なかった(M1で実測)。
上の「先頭が1文字欠ける」問題も、ヒントを入れたことで実際に起きなくなっている。

語彙は `stt.mjs` の `DEFAULT_PROMPT`。`config.json` の `whisperPrompt` で上書きできる。
長くしすぎると逆にその語へ引っ張られるので、間違えられて困る語だけに絞ること。

VAD(`vadModel`)は声のある区間だけをwhisperに渡す。無音や物音を渡すと、whisperは
「ご視聴ありがとうございました」のような学習データ由来の定型句を返す癖がある。
それでも出てきた分は `stt.mjs` で捨てている。

### 声紋の作り方は2つある(収集を勧める)

| | 何をする | 向いている場面 |
|---|---|---|
| `--collect` → `--build` | ふだん喋っている声をそのまま貯めて、あとで声紋にする | **イヤホンをしている間**。こちらが良い |
| `--enroll` | 台本を条件を振って15回読む | 静かな環境で一気に済ませたいとき |

**収集のほうが良い声紋になる。** 朗読と普段の喋りは声の出方が違い、実際に判定するのは
後者だから。ゲームの実況でも独り言でも構わない。何もしなくても貯まる。

#### 開始時にメーターが出る

`--collect` は本編に入る前に6秒間、入力レベルをバーで出す。
喋りながらバーが伸びるので、届いているかがその場で分かる。

```
【マイク確認】これから6秒、いつもの声で何か喋ってください。
  ──────────────────────────────┃ ここを超えれば録音が始まります

  ██████████                    ┃ 0.007
  ██████████████████████████████┃██████████████████ 0.740
  ○ 届いています(最大 0.740 / 必要 0.020)。
```

これを入れたのは、**「1時間喋って0件」を実際に疑う場面が起きた**から。
届いていないことは黙って起きるので、待っているだけでは原因が分からない。
届いていなければ、設定すべき数値を具体的に出す(止めはしない。判断は本人がする)。

#### まず届いているかを測る

収集も呼びかけも、声が録音開始のレベル(`wakeStartThreshold`、既定3%)に届かなければ
**何も起きない**。しかも黙って起きるので、1時間喋って0件という事故になりうる。

```bash
node palwatch.mjs --miccheck   # ふだん座っている場所から実行する
```

音量が届いているかと、そこから聞き取りまで通るかを両方見る。
音量が足りていても言葉にならないことがあるため(距離・周囲の音)、両方見る必要がある。

`--collect` 側にも、90秒なにも拾えていなければ知らせる仕組みを入れてある。

#### 短い発話も捨てない(2026-08-04)

最初は「4文字未満の発話は捨てる」にしていたが、これは用途を取り違えていた。
FPSのコール(「敵3、右」「回復入る」)は短いのに声はしっかり出ていて、
**材料としてはむしろ良い**——興奮した声や大きい声は、台本の朗読では絶対に採れない。
文字数で切ると、その良い材料だけを狙って捨てることになる。

判定は音の長さに変えた(0.8秒以上)。声紋に効くのは長さのほうで、
文字数のチェックは「物音ではなく声だったか」の確認にとどめている。

#### 幅が採れているか見る

件数だけ多くても、同じ調子の声ばかりでは声紋の幅は広がらない。
`--voicebank` が声の大きさの分布を出すので、偏っていないか確認する。

```
  声の幅   :
    静かめ     2件  ███████
    ふつう     1件  ███
    大きめ     4件  ██████████████
```

**片方に寄っているときは要注意。** たとえばFPSの試合中だけ集めると
大きい声ばかりになり、あとで落ち着いて「ルナ、今何体いる」と呼んだときに
下限を割って弾かれることがある。呼びかけるときの調子の声も入れておく。

#### 堂々巡りを状況で断ち切る

声紋を作るには本人の声が要る。本人の声かを判定するには声紋が要る。
`--collect` はこの循環を、機械ではなく**環境**で断ち切っている——
イヤホンをしていれば、通話相手の声もゲーム音もマイクには入らない。
その間なら判定なしで集めてよい。

**保証しているのは仕組みではなく状況**なので、書き起こしを画面に出して
その場で見えるようにしてある。違う声が混ざったら気づける。あとから消せる。

```bash
node palwatch.mjs --voicebank --all     # 全件見る
node palwatch.mjs --drop 2026-08-04T12  # idの一部で消せる
```

`--build` は平均を出す前に外れ値も落とす。ただし境目は固定値にしていない。
最初は0.60と決め打ちにしたが、**混ざりものを入れて試したら1件も落ちなかった**。
本人の声どうしでも0.86〜0.94に散らばるので、「いくつ以下なら別人」は
集めた声の分布を見ないと決まらない。中央値からの散らばり(MAD)で測っている。

同じ試験で、本人7件＋別人2件を投入したところ:

```
1回目: 中心 0.879 / 散らばり 0.009 → 下限 0.854
  離れている2件を除外:
    0.767  ★別人 K_1
    0.767  ★別人 O_1
材料: 7件  一致度の下限 0.894(汚染時は0.766)
```

これで捕まるのは「明らかに違う声」まで。**声質の近い人は通る。**
最後の砦は仕組みではなく、イヤホンをしている状況と、書き起こしを見て気づくこと。

### 使いながら精度を上げる

**登録は1回で終わりにしない。使いながら貯めて、作り直す。**

`--enroll` で録るのは1セッションぶんの条件でしかない。実際に使う場面はもっと幅がある
——早口、小声、離れている、ゲームの音が鳴っている。
声紋の下限を決めるのは**いちばん条件の悪い1件**なので、その幅が入っていないと、
実際に使うたびに下限を割る。だから登録の台本は条件を振ってある(15回、条件5種)。
なかでも「動画を流しながら」が効く。それがふだんの使用条件そのものだから。

貯めるほど下限が上がり、**しきい値を上げられる**。声を足すのは甘くすることではなく、
絞れるようにすること。

```
--wake で使う  →  はっきり本人だった録音だけ貯まる
                  弾いた音も残る(較正の「弾きたい側」の実データになる)
--voicebank    →  貯まり具合と、最近の書き起こしを見る
--relearn      →  貯めた声で作り直し、上げられるしきい値を提示する
```

#### 学習が壊れないようにしている仕組み

誤って通った他人の声をそのまま学習すると、声紋がそちらへ寄る。
寄ればもっと通りやすくなり、さらに寄る。放っておくと戻らない。歯止めが3つある。

1. **採用の門を反応より高くする**(`admitMargin`、既定 +0.08)
   反応はしたが自信は無い、という録音を学習に混ぜない。
2. **最初の登録を錨として残す**
   作り直しても必ず含まれ、全体が少しずつ流れるのを引き戻す。
3. **作り直すとき、1件ずつ錨と照らして落とす**(`relearnFloor`、既定 0.70)

3番目が要。最初は「作り直した重心が錨からどれだけ離れたか」だけを見ていたが、
**これは効かなかった**。平均は多数決なので、17件中10件が別人でも重心は0.13しか動かず、
ずれの下限(0.85)を通過して汚染された声紋がそのまま保存された。

混入を止めたいなら、混ざったあとを測るのではなく、混ざる前に1件ずつ落とす。
同じ試験を1件ずつの判定に変えたところ、別人10件を名指しで除外し、声紋は無傷だった。

| | 錨との一致度 | 結果 |
|---|---|---|
| 本人の別発話 | 0.878 | 採用 |
| 別人10件 | 0.596〜0.674 | 全部除外 |

#### 貯めたものは他でも使える

`voicebank/` の中身は wav + 書き起こし + 時刻という素直な形にしてある。
別のツールから同じフォルダを読めばいい。`voicebankDir` で場所を変えられる。

- 呼びかけ語の検出モデルを自分の声で作る
- 聞き取りの誤りを集めて、語彙のヒント(`whisperPrompt`)を見直す
- 別のアシスタントで同じ声紋を使う

```
voicebank/
  index.jsonl    1行1件。時刻・書き起こし・一致度・音量・通/弾
  embeds.json    声紋ベクトル(id → 256次元)
  samples/       wav本体
```

### 設定のしかた

```bash
node palwatch.mjs --enroll     # 条件を振って15回録り、声紋の土台にする
node palwatch.mjs --calibrate  # 自分の声と動画の音を録り、しきい値を2つとも出す
```

`--calibrate` は「あなたの声」と「弾きたい音(YouTubeなど)」を実際に録って、
音量と声紋の両方について分かれているかを確かめてから数値を出す。
重なっていればその旨を表示するので、その値は使わない。

**動画は、ふだん見ているのと同じ音量で流すこと。** 較正した条件でしか当たらない。

声紋が未登録のうちは判定せず素通りする(設定を足しただけで反応しなくなると困るため)。
音声はすべてMac内で処理され、外には出ない。

- `wakeMinRms` — この音量未満は聞き取りにかけない。`--calibrate` が出した値
- `speakerCheck` — `false` で声紋の判定を切る
- `speakerThreshold` — 本人と見なす一致度。`--calibrate` が出した値
- `voiceprintPath` — 声紋の保存先(既定はこのフォルダの `voiceprint.json`)
- `collectVoice` — 使いながら声を貯めるか(既定 `true`)
- `admitMargin` — 学習に採用する余裕。反応のしきい値 + この値(既定 0.08)
- `relearnFloor` — 作り直すとき、錨とこれ未満の録音は落とす(既定 0.70)
- `driftLimit` — 落としてもなお錨から離れていたら中止(既定 0.90)
- `voicebankMaxSamples` — 貯める上限(既定 200)。錨は数に入るが消えない
- `voicebankDir` — 置き場(既定はこのフォルダの `voicebank/`)
- `buildOutlierK` — `--build` で外れ値を落とす強さ。中央値から散らばり×この値(既定 3.0)
- `buildFloor` — 散らばりで測れないときの絶対の下限(既定 0.60)

### うまく動かない時

`config.json` で調整する。

- `wakeWords` — 呼びかけ語。複数指定でき、既定は `["ルナ", "るな"]`
- `wakeStartThreshold` — この音量以上で録音を始める(既定3%)。**大きくすると小さな物音を拾わなくなる**
- `wakeSilenceSec` — 何秒黙ったら切るか(既定1.0秒)
- `wakeDebug` — `true` にすると、呼びかけ以外の聞き取り結果も表示される。調整に使う

**それでも全く反応しない場合、まずシステムの入力音量を疑う(2026-08-03に実際に発生)。**
`config.json`をどういじっても直らないなら、Macの「マイク入力音量」自体が低い可能性が高い。
`osascript -e "get volume settings"`で`input volume`を確認し、低ければ
`osascript -e "set volume input volume 100"`で上げる。
実際にこのプロジェクトでは入力音量59%の状態だと`rec`の録音振幅が0.01程度(環境音レベル)
にしかならず、100%に上げたら0.2程度まで上がってwhisperが正しく聞き取れるようになった。
マイクの権限(システム設定→プライバシーとセキュリティ→マイク)がすでに許可済みでも、
この音量設定自体は別問題として残るので注意。

**ゲーム音が鳴っている環境では誤検知が増える。** ヘッドセットを使うと大幅に改善する。
それでも実用にならなければ `--talk`(キーを押す方式)に戻せる。返答の中身は同じ。
